# CrossBorder AI Cost & Risk Router

A runnable, transparent portfolio project for routing multilingual cross-border
support requests between an economy and a premium model tier.

The project is based on a real business pattern - routine logistics/account
questions are frequent, while legal, tax and high-value cases have a higher
failure cost. The public repository uses **deterministic synthetic data only**.
It contains no customer records, company API keys or proprietary interfaces.

## What is implemented

- Chinese, English and Korean keyword-based intent classification.
- Risk-first policy: high amount, high risk and low confidence use premium.
- Typed masking for email, phone and order identifiers.
- 600-record reproducible synthetic benchmark.
- Modeled premium-only baseline and routed cost comparison.
- 28 automated tests, 97% package branch coverage and GitHub Actions CI.
- CLI demo with no paid API or external dependency.

This version intentionally does **not** claim a trained BERT classifier or live
production model traffic. A provider adapter can be added after the routing
policy is validated against authorized data.

## Reproduce the benchmark

Python 3.10+ is sufficient:

```bash
python -m unittest discover -v
coverage run -m unittest discover -v
coverage report
python -m core.benchmark --count 600 --output benchmark/results.json
```

The committed benchmark result is generated by the same command. The modeled
prices are fixed assumptions, not current vendor quotes.

Coverage is a regression signal, not evidence that synthetic accuracy transfers
to production traffic.

## CLI example

```bash
python -m core.cost_router \
  --text "Where is my parcel for order #ABC-12345?" \
  --amount-usd 50
```

High-risk example:

```bash
python -m core.cost_router \
  --text "This order involves a contract breach and possible lawsuit" \
  --amount-usd 2500
```

The output includes the detected intent, confidence, route, reason, review flag
and masked text.


## Design principles

1. Hard risk rules override cost optimization.
2. Unknown and low-confidence requests fail toward the premium route.
3. Classification and policy are separate and independently testable.
4. PII is masked before classification or any future external provider call.
5. Every public metric is reproducible and states its data boundary.

## Production gaps

This is a portfolio MVP, not a hosted production gateway. Production deployment
would still require authenticated tenant APIs, durable idempotency, provider
adapters, rate limiting, circuit breakers, observability, authorized real-data
evaluation, data retention controls and human-review workflow integration.
